# Local fixture speech HTTP runtime

This opt-in local operation connects the existing owned admission/claim/settlement store to the keyless fixture coordinator. It performs synthetic tone lookup, not speech recognition. No vendor factory, credential, microphone, model submission, real action or public speech is enabled. The upload UI has no fixture execution button in this increment. Current user/private/public profiles and schema11 remain unchanged.

The separate [owned status read boundary](fixture-status-reads.md) now supplies bounded metadata/recovery and exact privacy-checked result GET without new execution or charges. It uses this same explicit local/public-denied capability.

`SAATHI_LOCAL_FIXTURE_SPEECH=false` is the default, separate from upload/privacy flags. Literal `true` requires a reviewed fixture-a/b STT role with synthetic-stt-v1 and supported fixture languages; disabled/live roles fail configuration before opening the database. Configuration and app registration independently refuse public mode. The entry creates one coordinator runtime only for this explicit local profile. `/health` reports `fixture_speech` separately; `speech` and `actions` remain false. A configured chat key cannot enable this operation.

`POST /api/media/:id/fixture-stt` accepts exactly:

```json
{"request_id":"owned-fixture-request","consent_revision":1}
```

The path must be a media UUID, without query fields. The existing host/origin/session/CSRF/rate/strict-JSON60KB gates run first. Owner, roles, hashes, expiry, private capabilities and provider selection are server-owned; client overrides/extra fields are rejected. Current processing consent is required, separately from storage consent. Admission reserves a durable attempt/audio-unit allowance before any one-shot claim. These units are fixture limits, not actual currency accounting or live-provider permission.

Success/status uses HTTP200 and an explicit projection: admission ID, request ID, media ID, consent revision, mode=fixture, a fixed synthetic-lookup notice, state, pending, expiry and current privacy-checked outcome. No audio/owner/token/hash/role bundle is returned. Completed fixture text remains labelled through its source metadata. A failed/unsupported tone returns a fixture failed outcome, never invented recognized speech. Arbitrary uploaded WAV files cannot be presented as ASR results. Pending status is not worker completion; a disconnected client may not receive it at all.

Exact same-request posts preserve saved identity/results without another unit charge or adapter replay. Changed input conflicts; new requests still need current fixture roles/consent/budget. Current-role checks at claim prevent old reservations from becoming a live-adapter invocation. Cached completed evidence can retain its original fixture snapshot after a trusted role change. Revocation/deletion/expiry suppresses or clears retained output through existing privacy semantics; original ledger records remain. The exact HTTP session is rechecked after asynchronous execution, so another active session for the owner cannot rescue an expired cookie.

Pre-aborted requests reserve nothing. In-flight cancellation/deadline can return bounded pending status while an abort-ignoring worker still holds its slot. Only actual acknowledgement or exclusive process-loss recovery releases handed-out work. Late text is not retained after cancellation/revocation/expiry. No attempt refund, automatic retry, background queue or consent regrant is added. Unexpected execution/acknowledgement errors are fixed503 responses. The coordinator's trusted assertAccepting guard also blocks new reservations after a late background acknowledgement failure, before another owner can be charged.

In the explicit fixture profile, shutdown first stops runtime admission and terminally signals its coordinator. It then starts Bun's graceful server stop, drains actual worker acknowledgement, waits for HTTP closure, and closes storage once. Concurrent signals reuse one shutdown promise. No forced store close occurs on drain/acknowledgement failure; the entry reports a fixed error and sets exit status1 without forcing exit. Actual process loss still releases the kernel guard and permits the existing interrupted/no-replay recovery. Drain may wait indefinitely for an abort-ignoring trusted test adapter. Default/public startup and force-stop behavior remain unchanged. This ordering follows [Bun Server.stop](https://bun.sh/reference/bun/Server/stop), whose graceful form waits for active responses, and Hono's [middleware registration order](https://hono.dev/docs/guides/middleware#execution-order).

Tests use fresh synthetic databases/tones with trusted blocked-adapter injection only. They cover opt-in/public/live-role refusal, strict ownership/consent, duplicate/cache/privacy, durable quotas, invalid tone, pre/in-flight abort, exact-session expiry, immediate/late acknowledgement failure, stop-before-reservation, idempotent shutdown, real loopback/kernel guard/drain/reopen and no replay/refund. A Linux-only child starts the actual application entry with a credential-free environment, executes fixture HTTP and sends SIGTERM to verify graceful exit/persistence. Windows does not deliver that POSIX signal; its separate real Bun lifecycle test still runs. Packed public smoke proves the operation absent. See HANDOFF for exact test/source/CI evidence.

A fixture-result review UI and any later real ASR require separate work. Live speech needs reviewed provider access, actual cost/admission policy, consented language-quality evidence and runtime cancellation/reconciliation. This local fixture flag cannot grant any of those capabilities or enable WhatsApp.
