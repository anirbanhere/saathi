# Bounded cached native read validation

Previously savedPlanRead parsed persisted JSON and cast it to ReadResult without checking its target, shape or mock/draft semantics. Corrupted rows could claim a foreign task, live evidence or verified manual output, and malformed JSON escaped as a raw parse failure. The cached path now validates evidence before returning it, preserving existing valid cached/restart/cancellation behavior.

A SQL CASE accepts only text payloads of at most64,000 UTF-8 bytes before materialization in JavaScript. Strict schemas enforce the exact read-only envelope, target ID, bounded unique step IDs, safe timestamps, known tools/statuses, bounded strict outputs and aggregate priority. Mock clinic output has only mock slots with completed/unavailable matching availability. Unskipped manual output must be an unverified draft requiring user action. Skipped steps carry a reason/requires_user_action; unskipped failure reasons apply only to clinic lookup. Unknown fields, live markers, positive verification, mismatched aggregate status, duplicate steps, BLOBs, malformed/oversized data and foreign targets fail with a fixed503 message.

The invalid row is retained. No repair, deletion, overwrite, automatic retry, adapter replay, quota release, new receipt or migration follows. Ownership remains established by TaskPlans before this internal helper; no new route or public grant is introduced. Cache validity does not grant execution, prove external truth, cryptographically authenticate the SQLite file, or prove every provider-content field. The later context-binding increment below checks saved steps/manual instructions/date/prerequisites; remote-provider authentication and other content truth remain separate work. Public/source schema, approval/spend/speech/channel gates and the separately pinned3b81c85 rollout candidate are unchanged.

Regression first reproduced corrupt cache acceptance, then focused cache/native reads7/83 pass. Mutations include wrong target/mode/tool/verification/status, extra fields, duplicate steps, malformed/oversized/BLOB payloads and impossible manual failures. Usage/events and raw retained payload are unchanged. Valid restoration returns cached evidence, and corrupt mock cache invokes no second lookup. Fresh-context adversarial review found an impossible unskipped-manual failure combination; tightening it and a regression closed the gap, follow-up found no additional issue. Cross-model skipped non-interactive. Full suite/types/build evidence is in HANDOFF; no browser change/provider call or real data used.

## Exact saved-plan context

The cache helper now reads payload and saved task input/plan in one LEFT JOIN, bounding each selected text field to64KB before that helper materializes it. Missing/invalid context fails503 rather than treating the cache as absent. Strict saved input and a ready stored plan are validated without invoking a model or adapter. Result count/order/step ID/tool must match the stored plan; skipped state must match earlier prerequisite outcomes. Manual draft text must equal the planned instructions, and mock clinic dates must equal the separately confirmed date enforced by plan validation.

Current task state is deliberately not a freshness or cancellation gate: already-saved read history remains readable after cancellation and restart. Corrupt cache/context remains retained, with no rewrite, replay, lookup, quota or event mutation. Coherent edits to manual text, valid step IDs, tool identity, result count, confirmed date or skipped state are rejected; restoring valid data returns the original cache without another lookup. Oversized saved input also fails at the helper boundary.

This is not a whole-HTTP memory cap: TaskPlans.view still has its pre-existing JSON projections before invoking the helper. It is not file signing, protection against coordinated coherent edits of both plan and observations, validation of all clinic content or proof of external completion. No new schema, grant, provider or public rollout follows. Fresh-context review found no actionable issue; cross-model skipped non-interactive. Exact tests/build/CI evidence is in HANDOFF.
