# Durable internal speech budget holds

Source schema13 introduced `SelfHostedStore.sttBudgetHolds`, separate from fixture admission/claims. Normal startup provides no `sttBalanceReader`, so `reserve` is disabled. There is no runtime flag, HTTP/model tool, provider factory, active policy, approval, worker claim, automatic release or remote settlement interface. Source14 adds only the explicit internal confirmed-unissued cancellation described in stt-unissued-cancellation.md. Even a successful synthetic hold returns `executionAllowed=false`. The existing public source27de098/schema7 and private profiles have not been opened or upgraded.

A trusted caller supplies owner context resolved from its authenticated session. The journal checks an active session for that owner; possession of an owner ID alone is not caller authentication. Do not expose these methods without the existing exact-session/CSRF/ownership boundary. `reserve(owner, request)` accepts only request ID, owned media ID, consent revision, catalogue provider/account/revision and optional narrowed ceilings. It cannot accept a client balance, estimate, role, owner or execution flag. Default catalogue content and effective per-request pin bytes/hashes are both retained. Historical `get(owner, id)` and exact duplicate recovery return scalar hold metadata without audio, private hashes, canonical profiles or tokens; they do not renew consent. Recovery may describe a hold whose media consent has since expired or been revoked.

The optional balance reader is a deliberately injected, synchronous trusted cache observation interface. Bootstrap never installs one. This increment does not verify account ownership, vendor pricing, credit eligibility, real balance provenance or external account activity. The reader receives only frozen provider/account/currency labels and returns strict labels, observedAt and availableMicros. Extra fields and unknown/stale/future evidence deny. Real Promises are rejected and their late rejection is consumed without projecting/logging its payload; this does not cancel work a mistakenly supplied async reader already started. There is no async/network reader support or permission to add a vendor call here.

Observation acquisition happens before the immediate SQLite reservation transaction. A failed hold must not roll back a separately committed privacy action made during observation. Reentrancy is denied, and the transaction rechecks the clock, owner session, exact schema/guards, complete stored records, pending owner, current consent and actual WAV/hash evidence. It then recomputes prospective budgets with the canonical preview and inserts the hold atomically. A request committed by another connection during observation is recognized as a duplicate or included in counters before reserving. No external callback runs while the transaction owns the write lock. Balance freshness, tariff validity, consent expiry and active session are checked against a fresh decision clock after bounded ledger/WAV validation inside that transaction; snapshots are observations, not an atomic lock on vendor credit.

Attempt/audio/lifetime record counters aggregate the same provider account across all models, tariffs, policies and currencies; monetary counters and outstanding balance are scoped to provider-account-currency. Daily counters use UTC, lifetime rows never reset, and all earlier-day holds remain outstanding against the current balance. One pending owner applies across accounts/currencies. An additional deployment-wide hard5000-row bound cannot be widened by profile configuration. Every bounded journal record is revalidated before constructing authoritative local usage counters, using exact integer arithmetic; malformed stored content or cost fails closed. This is intended for bounded internal development, not high-volume credit accounting: the aggregate check scans at most5001 rows and the5000-row test takes about3 seconds locally.

The STRICT table has fixed update/delete rejection guards, a unique pending owner and no cascading owner/media foreign key. Media revocation/deletion cannot clear unresolved cost history or refund units. Canonical default policy references remain protected by the catalogue. No audio/transcript/key is stored in holds. Row/schema revalidation and the shared kernel ownership guard are application integrity controls, not protection against an administrator replacing the database. No whole-account erasure or secure WAL/backup deletion is claimed.

Current holds are never-dispatched local reservations. Source14 adds explicit confirmed-unissued cancellation; other holds remain held across restart, day/policy changes and privacy actions. There is deliberately no automatic expiry/refund or fixture-style startup interruption. Before enabling any execution, implement an independently reviewed lifecycle that binds the actual immutable STT role, account grant, current consent/hash, one-shot worker ownership and provider-specific idempotency/settlement. Distinguish a confirmed never-dispatched release from unknown remote financial outcomes; local process loss alone cannot release a remote unknown. Real speech, consented quality evaluation and public setup remain separate gates.

Opening current source14 on a supported earlier profile performs an additive migration. Older binaries refuse14; an existing-data rollout requires its own consistent backup/upgrade checkpoint and has not been performed. Media maintenance accepts genuine11/12/13/14 only because their media/claim schema is identical. It validates the same media guards and never migrates or changes holds/catalogue data. Unknown future versions remain refused. Fresh synthetic migration fixtures preserve completed fixture results, media, policy metadata, chat and inference usage; a failed migration leaves its version unchanged and releases database ownership. Exact tests/CI/source evidence are in HANDOFF.md.
