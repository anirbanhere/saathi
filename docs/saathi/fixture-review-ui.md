# Local synthetic speech result review

The development console has a separate **Review a fixture speech test** panel. Health must explicitly report fixture speech and local media controls enabled and public mode false. Default/public mode hides it and makes no media/fixture API request. The existing flags remain false by default. This feature does not deploy the branch, migrate an existing profile or enable live speech.

The panel lists eligible owned, unexpired short WAV clips with recorded processing consent and an en/hi/ta or unspecified hint. This is candidate selection, not proof of synthetic content or a new processing grant. The server rechecks permission, revision, fixture role and durable limits. Known generated tones produce preset text; arbitrary audio fails lookup. No microphone, playback, ASR, model reply, task, external provider or transaction is invoked. There is no transcript-to-chat send control.

**Run a new fixture test** creates one request ID and pins that ID, clip ID and exact consent revision in this tab. A new run uses a fixture allowance. Unknown network outcomes retain the same identity and lock selection; an explicit retry sends that same identity. **Stop fixture request** aborts the HTTP request cooperatively: it does not prove worker acknowledgement or rollback. Known pending work offers saved-status checking instead of another POST. No automatic polling, retry, reload resend or persistent browser audio/request storage is added.

**Refresh clips and tests** reads candidate metadata and the bounded recent-attempt list. It does not fetch every transcript. **View fixture result** reads exactly one owned saved admission; **Check saved status** recovers the pinned attempt by known admission ID or matching request/media/revision in recent metadata. These reads do not rerun work or consume an allowance. The recent list is bounded, not complete historical pagination. Reload clears tab-only intent and shows saved metadata without automatically opening results or submitting work.

**Refresh and clear selection** first refreshes authoritative metadata and then releases the tab-only intent. It does not cancel, delete or refund an existing attempt. If that read fails, the intent stays pinned. A confirmed POST followed by a failed history read is labelled separately; a history failure does not turn a confirmed result into an invitation to replay it.

Results distinguish completed, failed, pending and unavailable text, always with synthetic labels. The display checks fixture identity/source and bounds text; DOM text nodes preserve markup literally. Historical completed state is not current permission. Result GET uses the server's current consent/retention projection. Revoke/delete intent in the privacy panel immediately clears cached result text and candidate choices before the mutation; it neither grants processing nor signals a worker. Refresh also clears cached detail before reading. Revocation cannot recall copies already returned, and another tab's changes are seen only on a subsequent request; no push invalidation or continuous expiry timer is claimed.

The console shares busy, error and keyboard-focus controls with the other panels. Stop stays available during its own request while other submissions are disabled. Successful operations return focus to refresh; ambiguous POST failure returns focus to saved-status checking. New module assets are explicitly served and packaged, and packed public smoke still proves fixture operations absent.
