# Local audio selection and consent console

The development console now has a separate **Save an audio clip** panel. It appears only after health explicitly reports local uploads and local privacy controls enabled and public mode false. Default/public mode hides the panel and makes no media request. The existing flags remain false by default; opening the page cannot activate an upload route or provider. No deployment or existing-profile upgrade is implied.

Select one supported PCM16 WAV up to2MB/60 seconds and explicitly check storage consent. Storage and optional processing consent both start unchecked. The interface explains that access expires within15 minutes or at session expiry, while expiry does not physically delete bytes; explicit deletion/cleanup and backups are separate. No microphone recording, playback, transcription, model submission or task execution is added. A language hint is not detected-language or quality evidence.

The panel uses the [existing raw-WAV contract](local-media-upload.md), current CSRF and the shared busy guard. It sends no filename/path header. The server remains authoritative for ownership, WAV evidence, quotas and retention. Success shows returned clip status/expiry/recorded consent and refreshes the existing privacy list. Inputs/consents reset after a confirmed result. A failed list refresh after confirmed upload is labelled separately and does not invite a new upload of already-confirmed content.

An ambiguous error retains the exact original File/request ID/consent/language in this tab. File and consent controls stay locked; **Retry same upload** sends that same identity once per explicit click, with no automatic retry. **Stop upload** aborts the transport but does not claim storage rolled back. **Check saved audio and clear selection** refreshes owned metadata before releasing the retained selection; it does not delete any clip. A definitive stale-workspace error instructs a page refresh. Retry state is in memory only: closing/reloading the tab loses it, and no recovery or duplicate guarantee across browser restart is claimed. No recording is written into browser storage or development memory files.

The existing busy guard blocks conflicting chat/plan/appointment/media controls while retaining the upload stop action. Status text uses safe text nodes/live regions, field labels are explicit, and focus returns to the file input after success/clear. Error text is fixed rather than rendering raw stream/provider payloads. A new upload.js fixed asset is included in serving/build allowlists and the packed public smoke; the asset being present does not enable public uploads.
