# Read-only STT access-blocker review

`sttBudgetHolds.reviewAccess(owner, holdId)` is an explicit internal diagnostic over an owned hold. It consumes no units, changes no hold/snapshot/consent state and never issues a grant. There is no HTTP/model tool, account connection, provider call, key loading, worker or migration. Default bootstrap supplies no reviewer. Public/private profiles and public source27de098/schema7 remain untouched.

The enclosing service must authenticate the caller and resolve its owner. Active owner/session, owned hold, immutable policy/role evidence and current processing-consent/media identity are checked before review. Closed holds, unbound snapshots and unavailable/revoked media produce fixed local blockers without consulting an account cache. A valid recorded hold with no reviewer returns requires_auth/account_not_connected. This is a current blocker, not a claim that all other admission requirements are satisfied. Original get/history reads remain metadata only and never call the reviewer.

An optional server-injected synchronous local `SttAccessReviewer` receives frozen minimal owner/hold/provider/account/model/currency, original reserved ceiling/language, policy/role content IDs and a check timestamp. It receives no credential, audio, media hash, transcript or private execution token. Request options are explicitly marked unbound. No callback runs inside a database write transaction; current session/hold/consent are rechecked after it, so independent privacy, cancellation or expiry cannot be hidden by stale cached context. Source storage faults stay fixed unavailable errors instead of asking a user to regrant consent.

The port accepts only strict cached blocker outcomes: requires_auth with fixed account/grant codes; requires_user_action with fixed provider-term/retention/spend/request-option codes; or unavailable/account_check_unavailable. Positive/ready/verified/allowed blobs, extra free text, wrong code/status pairs and malformed results are unsupported. Throws and real Promises become fixed unavailable diagnostics, with late Promise rejections consumed without projecting their payload. Unsupported async work is not cancelled; the contract forbids network/async callbacks and installs none. Returned reports project only kind/status/code plus executionAllowed=false, never private context.

This intentionally provides no positive admission outcome. A report, callback presence, key, snapshot or matching digest cannot become a permit. A future independently reviewed verifier/grant issuer must establish actual account ownership, authority, scope, revocation/expiry, retention/request-option policy and one-shot worker identity before any dispatch. Fresh tariff/balance checks, actual WAV/hash inspection, durable unknown-charge reconciliation and user/channel approvals remain separate; this diagnostic refreshes none of them. No remote refund or automatic cancellation follows from a blocker.

Synthetic tests cover the unconfigured port, no quota/observer replay, fixed context/projection, unsupported positive or forged responses, exceptions/async rejection, foreign/expired ownership, local unbound/closed/media blockers, independent privacy/cancellation/session changes and storage failure handling. Existing role/cost/consent/cancellation tests remain mandatory. Exact source, local/Linux gates and packed evidence are in HANDOFF.md. Source schema stays15; no existing-data upgrade is authorized by this increment.
