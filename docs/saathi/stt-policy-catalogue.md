# Internal immutable speech policy catalogue

This increment adds schema12 metadata storage under the existing SelfHostedStore ownership guard. `sttPolicies.register(profile)` stores only a recomputed default canonical policy pin, keyed by provider/account/revision. Exact duplicates return the original record/time even at capacity; changed content under that key conflicts. Different provider-account scopes are independent. The configured lifetime limits can only tighten the hard defaults of1000 global rows and100 rows per provider-account scope. They are process configuration, not a persisted policy ratchet; every registration recounts durable rows. There is no automatic registration, active-policy selector, user route, vendor access, approval, reservation or lease.

`get(scope, revision)` is a trusted internal read, not account authentication. Both methods revalidate stored canonical bytes/hash/scope before returning frozen metadata. The catalogue accepts declared profile labels; it does not verify account existence, pricing, credits or operator authority. A future verified service identity/account grant is required before live use. Do not expose registration to anonymous workspace users or models. Effective per-reservation limit variants stay outside this default-profile catalogue and must be bound by the later reservation identity.

The additive migration creates one bounded STRICT table and fixed update/delete rejection triggers; it does not modify media/claims, inference usage, threads or private data. Schema checks and an immediate write transaction reject changed/unknown catalogue guards before insertion. No eviction/update/delete API or background task is added. Corrupt canonical rows return a fixed storage error; they are never silently healed. These are application/database integrity controls, not protection against an administrator replacing the database file.

SQLite's [STRICT table rules](https://www.sqlite.org/stricttables.html) retain normal CHECK/UNIQUE constraints, and its [trigger RAISE contract](https://www.sqlite.org/lang_createtrigger.html) supports rejection without rewriting rows. Existing media-maintenance validation may accept11 and12 because their media/claim schemas are identical; it still validates its exact media guards, migrates nothing and cannot clear policy metadata. Unknown future versions remain refused.

Use fresh synthetic profiles for migration/duplicate/conflict/guard/quota/reopen tests only. Do not open existing private/public profiles with this branch: startup migrates supported older schemas, while older binaries reject12. Existing-profile rollout needs its own consistent backup/upgrade checkpoint. Public source27de098/schema7 remains unchanged. The next slice is authoritative atomic reservation, complete snapshot/budget checks and held-unknown outcome semantics from tasks/stt-live-ledger-design.md; catalogue rows do not grant that authority.
