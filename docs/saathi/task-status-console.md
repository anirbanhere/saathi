# Explicit saved status on owned task cards

Development appointment and draft-plan cards now offer Read saved status. The Help/status language selector controls English/Hindi/Tamil output. The card captures its already-owned kind/UUID; the human does not type implementation IDs, and card titles are used only for a bounded accessible label, never sent in the status body. Creating/rendering cards, changing language and loading/reloading the workspace do not issue status reads.

One explicit click uses the existing owner/CSRF /api/control-read contract. It bypasses appointmentAction/refresh and all legacy get/list calls, which can materialize expiry/audit. Shared busy/focus freezes the locale and suppresses overlapping clicks. Existing approval/cancellation/quote/nonces, task controls, model choice and pending execution state are untouched. Optional per-card renderer callbacks preserve existing component callers without the new control.

The browser checks returned target kind/ID, locale, format/intent/action=false/evidence scope, expected mock or draft_only mode, allowed state code, bounded message/notice/pending text and valid snapshot time before rendering. Pending=false requires no pending note; pending=true requires a bounded explanation. Unknown/foreign/mismatched/positive-execution responses cannot be shown as valid status. Invalid captured targets produce an unavailable text item without a request.

Each readout safely renders the timestamp, localized message, mock/draft notice and any pending note using textContent and preserved paragraph breaks. It receives locale language metadata and focus. Stored enum values are not substituted for human messages. The snapshot is checked at its recorded time in India; it does not certify plan/receipt content, live external completion or ongoing freshness. The new readout does not update the card's existing action controls or approve/reject anything. Normal task review/decision still enforces its own expiry/identity.

A20-second deadline aborts and suppresses late responses. Errors are fixed localized read-failure/session text with no raw server/provider echo; there is no retry, polling, model/provider/catalogue call, target-list fetch, quota release or mutation. The shared authenticated JSON parser is reused; field bounds are applied after parsing the server's small metadata reply, not a new streaming-body cap. Source schema15 and public schema7, existing profiles, deployment and all real speech/channel/transaction gates are unchanged.
