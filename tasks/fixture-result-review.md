# Next slice: owned fixture status recovery, then result review

Proposed follow-up to the local fixture HTTP/runtime slice, not implemented or a live/public speech grant. Reuse existing admission/settlement/privacy and UI helpers. Preserve current profiles, provider/spend gates, approvals, self-hosted state and contributor work. Use only fresh synthetic stores and generated fixture tones; no recording/provider/model call.

First add the smallest useful read boundary for owned saved fixture attempts: a bounded metadata-only recent list and an exact owned admission-ID status/result GET. Gate both with the same explicit fixture-local capability, default/public absence and parent owner/session/security middleware. Accept no owner/query/role/worker override. Read access must not claim/replay/charge/cancel work or grant processing. Review existing OwnedMedia.list as a pattern; do not fetch audio/private hashes/tokens or all retained transcripts merely to build the metadata list.

Result GET must use the canonical runtime projection and current consent/session/output-retention checks. A stale, revoked, deleted or expired clip must not expose old text even if its stored state says completed. Metadata reflects historical/current saved execution state, not a new consent or worker grant. Bound row count/order and single-result size; foreign IDs remain absent and repeated reads are side-effect free. Preserve durable attempt units, pending-worker slots, no-replay/no-refund and public-mode denial. Failed/stopping admission need not prevent an already-owned read while storage is safely open.

Tests first: no flags/public/programmatic denial; anonymous/foreign/expired exact session; UUID/query rejection; deterministic bounded list; SQL projection excludes BLOB/hash/token/outcome columns for metadata; reads do not alter state/ledgers or invoke adapters; current-consent suppression; saved evidence across reopen and hard-kill interruption; sanitized storage failure. Run scoped/server/frozen/format/audit/packed gates and exact-source Linux checks, then checkpoint the read increment before expanding UI.

Then a separate small fixture-review console may list saved attempts, run an explicitly labelled synthetic tone example for eligible owned media, and display bounded fixture-labelled text/status. Any new fixture POST needs an immutable request/media/revision identity with explicit same-request retry/pending recovery; current recorded consent is not a fresh lease. Do not silently regrant consent, automatically resubmit after reload, start a model/task, enable microphone/playback or present arbitrary audio as recognized speech. Use the new read APIs for refresh/recovery; no browser storage of recordings or credentials.

The eventual UI must require explicit local fixture+privacy capabilities/public=false, use safe text nodes and shared busy/focus/error/cancel helpers, and disclose that fixture lookup is not actual ASR. Verify on an isolated real browser with synthetic data, recording the existing native file-picker tool limitation accurately. Live speech still needs separate provider access, actual budget/admission policy and consented language-quality evaluation; this plan cannot authorize them.
