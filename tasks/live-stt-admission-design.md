# Next bounded slice: live STT admission design, without enabling it

The local fixture HTTP/read/review stack is implemented on development branches. Read HANDOFF.md, docs/saathi/fixture-review-ui.md, vendor-stt.md, stt-admission.md and stt-claims.md before expanding it. Do not rewrite fixture storage or turn a configured vendor role into execution authority. The next useful voice increment is a reviewable live-admission contract and offline executable policy; actual provider registration/calls stay separate.

First inspect existing role, vendor wire, media, ledger and claim boundaries. Specify the smallest server-owned policy needed to permit a future Sarvam/ElevenLabs STT operation: explicit per-provider enablement; immutable provider/model/price-policy pins; accepted language/duration/bytes; owner/global daily and lifetime units; separately configured currency ceiling and conservative reservation when price or billing unit is known; unknown price/credits fail closed; retry/cancellation/timeout/restart acknowledgement and no automatic paid fallback; exact owned consent revision; no public or browser-written override. Unit limits are not a currency-spend guarantee. Provider calls can be charged despite timeout, so never refund or replay unknown external outcomes automatically.

Record unresolved provider pricing/idempotency/status-query assumptions using official documentation. Documentation can guide a proposal but cannot authorize cost, new account access or consent. Do not guess an authoritative price or promise a hard monetary cap where the provider lacks enforceable billing controls. Keep real keys out of CI and require separate explicit permission for any bounded paid smoke test; the previous one-Meta planning approval was consumed and is irrelevant to speech.

Implement only an isolated pure admission-policy helper if the contract can be expressed without changing active fixture behavior, schema, provider factories or HTTP flags. Tests use literal synthetic policy inputs and no network: disabled/unknown price and currency mismatch; nonfinite/overflow/rounding values; conservative duration bounds; tightened owner/global caps; immutable safe projection without credentials; and denial of provider/model/client override. Default remains disabled. If durable integration needs new schema or external reconciliation, write that next task rather than smuggling it into this foundation.

Run the existing scoped/server/frozen/format gates, document exact evidence and open a stacked draft PR. Preserve all existing profiles/public schema7 deployment, contributor work, self-hosted state and approval boundaries. No real audio, vendor/key setup, model/speech call, public upload, message or deployment is part of this slice. A later separately tested executor must reserve durable budgets and authenticate one-shot claims before calling a provider; this helper alone must never be described as connected speech.
