# Bounded durable speech budget holds

Implement a trusted internal, default-disabled hold journal on additive schema13, separate from fixture admissions. This is an unexecuted local budget reservation, never a worker lease, verified vendor balance, approval, payment or provider call. No claim/release/settle/reconciliation route exists in this slice. All holds remain outstanding across restart, consent revocation, policy changes and UTC rollover until a later reviewed lifecycle contract. Preserve fixture recovery unchanged. Public/private existing profiles remain unopened.

`SelfHostedStore.sttBudgetHolds.reserve(owner, input)` is usable only with a deliberately injected synchronous trusted balance-observation reader. Production bootstrap supplies none. Input contains only request/media/consent identity, catalogue provider/account/revision and optional tightened ceilings. It cannot carry a role, balance, cost, owner or execution flag. Caller authentication remains the enclosing service responsibility. Existing active-owner session/media ownership and current processing consent plus actual WAV/hash inspection are checked in the immediate SQLite transaction. The catalogue supplies complete default profile content; the journal separately pins effective content/hash. Exact duplicate identity returns its original hold without new observation or units; changed content conflicts. Historical get never reads audio or implies current consent.

Balance input from the internal reader is strict provider/account/currency/observedAt/availableMicros only. No reader for current models/users/HTTP; no network/async operation. Acquire observations before the write transaction, then recheck freshness/session/current consent/usage inside it; failed holds must not roll back a separate privacy action. Declared observations do not authenticate accounts or verify prices/credits. An independently verified account grant/observation service, execution policy and reconciliation are prerequisites before any future live connection. Current code cannot execute a hold even when synthetic observations pass.

Aggregate account attempt/audio/lifetime units across all model/policy/currency revisions; monetary units by provider-account-currency. One outstanding owner is deployment-wide, including other accounts. Outstanding balance subtraction includes all owners/revisions/days in that currency. Apply an additional hard5000-row deployment bound. Read and revalidate bounded journal records before computing counters using safe arithmetic; no client snapshot or estimate is accepted. Price validity and fresh/nonfuture balance evidence must pass canonical preview under the same immediate check-and-insert transaction. Other clients can spend an external account balance, so this is no vendor credit guarantee.

The immutable STRICT journal has no owner/media cascading foreign key: privacy changes cannot erase unresolved local cost history. It stores opaque IDs, canonical policy content/digests, inspected duration/bytes/language, original timestamp, identity and exact cost; no audio, transcript or credentials. Fixed update/delete guards and schema validation deny tampering before writes. Row corruption fails closed rather than minting capacity. Current hold projection is bounded scalar metadata with executionAllowed=false and no private media hash/pin/token. No eviction/background cleanup. Existing-data upgrades require a separate consistent backup; older binaries refuse13. Media maintenance may accept genuine11/12/13 only because media guards are identical; it never migrates or edits holds.

Fresh synthetic tests: disabled reader/strict inputs; exact duplicate and changed effective identity; current ownership/consent/hash; account/currency/policy/day counters and held balance; all-owner pending; stale/future/unknown/throwing observations; atomic rollback, immutable guards, corruption, reopen/migration preservation. No production keys or outbound calls. The next slice must explicitly distinguish never-dispatched holds from unknown remote charges before adding release/claim/settlement; local process loss alone must never refund a remote unknown.

Implemented development evidence belongs in docs/saathi/stt-budget-holds.md and current HANDOFF. Actual role binding, verified account/observation access, never-dispatched release versus remote unknown, worker claims and settlement are still unimplemented and cannot be inferred from a budget hold.
